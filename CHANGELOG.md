# Changelog

All notable changes to Kombos, summarized here for GitHub. The full changelog - in all 4 supported
languages (Greek, English, French, German) - is always available inside the app itself, via the Help panel's
"Version history" tab.

## v4.9.7 — In-app update that installs, performance, dark installer, catalogue-only family

**Update really installs (found: the update was only announced, never installed)**: the toast / Settings → Updates now has **Install now**. It picks exactly `KombosSetup-<new version>.exe` from the latest release, requires a SHA-256 (the `.sha256` asset or GitHub's digest; no hash → no download), downloads with a 60 s no-data timeout and verification, starts the normal installer (UAC, same AppId → upgrade in Program Files, log in `%AppData%\Kombos\logs`) and then closes the app. If UAC is declined the app stays open. It never installs an older, equal or pre-release version. The installer is started by the app and is never killed by process tree (lesson from GearWin 6.9.9: a `/T` kill would take the setup down with the app); the old running copy is closed by Inno's Restart Manager (`CloseApplications`).
**CI (installer-e2e `from-latest`)**: now starts the previous published program, keeps it running while the new setup upgrades it, and asserts a real version increase, that the old process was closed, and the `KombosSetup-<x.y.z>.exe` naming the updater depends on. Runs on the runners after the push.

**Performance (§8 of the master plan)**
- Conversations are saved **atomically** (temp file + replace, previous copy kept as `.bak`, load falls back to it), **compact** JSON, in the **background**, **debounced** (700 ms) and one write at a time; flushed on exit, on folder change and before an update. Fixes the data-loss risk of a crash in the middle of a write.
- Long conversations render only the last 120 turns, **Show earlier messages** loads 120 more (cheap virtualization).
- Project import/indexing runs in the **background** (UI no longer freezes), streaming hash (files are not read into memory), files over 64 MB are not hashed, progress + cancellation.
- Local gateway: **413** for bodies over 1 MB (not read into memory) and at most 8 concurrent requests (**503** beyond).

**Installer**: follows the Windows light/dark theme (`WizardStyle=modern dynamic`), with dark tall pictures and transparent small PNGs (generated by `tools/make-wizard-art.py`).

**The Opsis family window keeps its downloads** (same as every app of the family): **Download / Update / Cancel** with confirmation (file, size, source), SHA-256 check, stall timeout, `.part` cleanup and no silent run. (A first draft of this version removed them by mistake; restored.)

**Hotkeys**: Ctrl+Alt+K and Ctrl+Alt+Space do not conflict with Windows defaults; if another application already holds one, the user now gets a tray notice and a tooltip instead of a silent failure (4 languages).

**Tests**: 108 (19 new): update planning (exact asset, newer only, hash required, API failure), installer start info (normal UAC installer, never silent, only a real `KombosSetup-x.y.z.exe`), atomic saves / backup fallback / concurrent writes, gateway 413 and limits, background indexing + cancellation, family downloads present, dark installer assets.

**Not verified**: the update was exercised by tests with a fake release API; a real download + UAC + upgrade on a runner happens only after the push (installer-e2e), and the dark wizard has not been seen on screen (the installer was compiled, never run here); the "Show earlier" button was not clicked in the live UI.

**Traces**: every project now builds deterministically (`Directory.Build.props`: `ContinuousIntegrationBuild`, `Deterministic`, `DeterministicSourcePaths`, `PathMap`), without PDB files in Release. A test (`HygieneTests`) scans our binaries (app, bundled plugins, `_ref`) and every tracked text file for build paths, machine/user names and the personal e-mail address (the debug path built into Microsoft's own apphost template is excluded, it is not ours). The five bundled plugin DLLs and `plugins-src/_ref/Kombos.dll` were rebuilt clean. New commits use the GitHub noreply identity.

A test reads the VersionInfo.

**Inno Setup 7**: `Kombos.iss` refuses to compile with anything older (`#if Ver < EncodeVer(7,0,0) #error`), `tools/release.ps1` looks for Inno Setup 7; CI installs Inno Setup 7.1.1 from the project's official GitHub release after checking its pinned SHA-256 and its Authenticode signature (Pyrsys B.V.).

**No hidden PowerShell**: the installer ended the old per-user program with `powershell -ExecutionPolicy Bypass` (hidden); it now uses WMI (`Win32_Process`) from inside setup, matching the exact old folder. (The app itself never ran PowerShell; a test keeps it that way.)

**Security scan**: the `security-scan` workflow's last run on the published release was green (Defender no detection, trace scan clean, gitleaks no leaks, no vulnerable NuGet packages); `dotnet list package --vulnerable` is clean for the current code.

**Not verified**: the CI path of the new Inno 7 install and the WMI process termination run on the CI runners only after the push (installer-e2e `from-per-user` runs the old program while upgrading); the security scan of this very version runs when the release is published.

## v4.9.4 — Install in Program Files, upgrade migration, installer CI, plugin trust

**Changed**
- The installer now installs **for all users in `%ProgramFiles%\Kombos`** (administrator, 64-bit). Settings and conversations stay in `%AppData%\Kombos`; the executable is no longer writable by a standard user.
- **Migration from the per-user install** (`%LocalAppData%\Programs\Kombos`): setup ends the old running program (exact path only), runs its uninstaller silently, checks that the uninstall entry and folder are gone (cleans what is left of its own old copy, stops with a message in all four languages otherwise), removes the old `HKCU Run` value and Startup shortcut, and carries the "start with Windows" wish over (pre-selected task; applied explicitly in a silent upgrade). One uninstall entry, one set of shortcuts, one `Kombos.exe`.
- "Start with Windows" is now the same per-user `Run` value the app writes itself (removed on uninstall); a silent uninstall never deletes your settings, an interactive one asks.
- Pascal uninstall key written with a single brace in code (`{`), `{{` only in `[Setup]` (the bug found in Opsis News Crawler).

**Added**
- **Free installer end-to-end CI** (`.github/workflows/installer-e2e.yml`, standard `windows-2022`/`2025` runners, a timeout on every step, a hanging setup/uninstaller fails the step): fresh install, upgrade from the old per-user release, upgrade from the latest release, smoke start (isolated data folder), uninstall and leftovers check. `tools/release.ps1` builds the setup the same way locally and on CI; PowerShell scripts were checked with the PowerShell parser. `windows-ci.yml` builds and runs the unit tests on every push.
- **Plugin trust model**: a plugin folder under `%AppData%\Kombos\plugins` (writable by the user) is only loaded when its SHA-256 (of **all** `.dll` in the folder, so a planted dependency changes it) equals the bundled plugin of the install folder, or the user approved that exact hash (prompt in 4 languages, "No" is the default; a *changed* plugin asks again). Installing from the gallery / Nexus approves it implicitly (explicit user action). 7 tests.

**Not verified**: the installer was compiled and parsed but NOT run on this PC (by rule); the end-to-end scenarios run on the CI runners only. UAC and per-monitor DPI cannot be tested there.

## v4.6.0 — Kombos Gateway + automatic agent continuation

Kombos Gateway (an explicit request after the "final" v4.5.0 - an exception, not scope creep): a new local HTTP gateway, inspired by the open-source OmniRoute (github.com/diegosouzapw/OmniRoute, MIT) - an OpenAI-compatible endpoint (`http://127.0.0.1:PORT/v1/chat/completions`) other tools (VS Code, Cursor, Claude Code, etc.) can point at instead of talking to a provider directly. Routes automatically to Kombos's central agent, with automatic **fallback** to the next configured agent if the first fails (rate limit/quota/network) - the same spirit as OmniRoute's "automatic fallback across 359 providers," but configured entirely through Kombos's already-friendly GUI (Settings → Behavior: one checkbox + one port), not .env files/a CLI/Docker/a separate dashboard - this is the "friendlier OmniRoute" that was asked for. Secure by design: listens ONLY on 127.0.0.1, never on the network. No code was copied from OmniRoute (different language/architecture - Node.js there, C#/.NET here) - only the idea of a single local gateway with automatic fallback was built from scratch, using the keys you've already entered into Kombos. Alongside it, new **automatic continuation when Claude nears/hits its limit** - explicit user request: the FIRST time, a pop-up proposes the first already-configured agent (Yes/No), and your choice is remembered from then on - Kombos automatically draws on that same agent next time, without asking again, so the conversation/project keeps going uninterrupted. Settings → Behavior has the enable checkbox plus a "Reset" button to pick a different agent later. The reply bubble always shows which agent actually answered - no silent/hidden switching.

## v4.5.0 — FINAL VERSION

Kombos is now complete as a multi-tool - no version is planned after this one. A large final wave: **🔄 Check for updates** (Settings → About, manual only, never a silent download/install) · **Import from ChatGPT/Claude.ai** (their conversations.json export files) · **Kombos Anywhere** (Ctrl+Alt+Space opens a mini quick-capture bar from anywhere, with an option to add the answer to the main conversation) · **Multi-window** (detach any conversation into its own window, with "Copy all as Markdown") · **/image** (real image generation inside the conversation via the OpenAI Images API, using the already-saved ChatGPT key) · **Real-time collaboration** (two computers pointed at the same sync folder see each other's changes automatically, via file watching) · **Local analytics dashboard** (tokens-per-session chart plus a per-tool breakdown, no telemetry) · **Plugin SDK v2** (a "New Plugin" wizard scaffolds a ready-to-build project) · **Nexus Marketplace** (install a plugin from a folder or Git URL) · **Artifact live preview** (real HTML/SVG/Markdown rendering in its own window, not just a code list) · an accessibility pass (AutomationProperties.Name on key icons/window controls). On "response speed/cost": the standing cache-friendly system prompt (since v2.8.0) already applies to every agent; real automatic routing to a cheaper tool or batching were evaluated and deliberately NOT built (it would mean Kombos silently overriding the user's own agent choice, or doesn't fit real-time chat) - an honest choice, not an oversight.
